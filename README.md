# Cyber Threat Prediction and Assessment Using Machine Learning

An extended machine-learning-based cyber threat detection and risk assessment framework using AWS Honeypot attack data. The project applies unsupervised anomaly detection algorithms to identify unusual IP behaviour and provides an interactive dashboard for IP analysis, threat monitoring and geographical visualisation.

## 📌 Project Overview

Cyberattacks generate large amounts of network traffic, making manual identification of suspicious activities difficult. This project aims to analyse honeypot network data and identify potentially suspicious IP addresses using machine learning techniques.

The implementation is based on the research paper:

**"Cyber Threat Prediction and Assessment With Machine Learning Approaches"**

The original research explores K-Means clustering and Gaussian Mixture Models (GMM) for detecting anomalous IP addresses.

This project extends the original methodology by introducing additional behavioural features, Isolation Forest, ensemble-based risk assessment and an interactive IP analysis dashboard.

## 🎯 Objectives

- Analyse network traffic collected through an AWS Honeypot dataset.
- Perform data preprocessing and feature engineering.
- Identify unusual IP behaviour using unsupervised machine learning.
- Compare different anomaly detection algorithms.
- Generate a combined risk score for suspicious IP addresses.
- Provide an interactive dashboard for IP searching and threat analysis.
- Support IP monitoring through an incoming IP text file.
- Visualise potentially suspicious IP addresses on an interactive world map.
- Save detection results for further investigation.

## 🧠 Machine Learning Algorithms

The project uses three unsupervised machine learning algorithms:

### 1. K-Means Clustering

K-Means groups similar IP behavioural profiles into clusters. IP addresses that are far from their nearest cluster centre may indicate unusual behaviour.

### 2. Gaussian Mixture Model (GMM)

GMM performs probabilistic clustering by modelling data as a mixture of Gaussian distributions. It helps identify IP profiles that have a low probability under the learned distributions.

### 3. Isolation Forest

Isolation Forest detects anomalies by isolating unusual observations using randomly generated decision trees. Anomalies generally require fewer splits to isolate.

### Ensemble Risk Assessment

The scores generated by the three algorithms are converted into percentile-based scores and combined to calculate an overall risk score.

The resulting score is used to assign a severity category:

- Low
- Medium
- High
- Critical

These categories represent model-assessed risk, not verified proof of malicious activity.

## ⚙️ Feature Engineering

The original research primarily uses the four octets of source IPv4 addresses.

This extended implementation uses **34 engineered behavioural features** for its main machine-learning models. These features are derived from the available dataset attributes and IP-level behavioural aggregation.

They represent information such as:

- Source IP characteristics
- Network protocol information
- Source and destination port behaviour
- Traffic and event frequency
- Time-related activity
- Geographic information
- Honeypot interaction patterns

Feature scaling is performed using `StandardScaler` before model training.

## ⚡ Real-Time IP Analysis

An additional feature of this project is the ability to analyse IP addresses through an interactive dashboard.

The system supports:

1. Searching an IP address through the dashboard.
2. Checking whether an IP exists in the trained honeypot profiles.
3. Estimating risk for an IP that is not present in the original dataset.
4. Displaying risk score, severity and available network information.
5. Showing approximate geographical information on the map.
6. Monitoring newly added IP addresses through `incoming_ips.txt`.
7. Replaying historical honeypot events to demonstrate event-by-event analysis.

**Note:** This implementation provides real-time IP querying and file-based monitoring. It does not directly capture live packets from a network interface.

## 🌍 Interactive Threat Dashboard

The project includes an interactive web dashboard with:

- IP address search.
- Risk score and severity display.
- Country and geographical information.
- Interactive world map.
- Threat filtering and marker visualisation.
- Detailed IP information.
- Separate map view.

Geographical coordinates obtained through IP geolocation are approximate and should not be interpreted as the exact physical location of a device or person.

## 📊 Model Evaluation

The following metrics are used to evaluate clustering quality and model selection:

| Metric | Purpose | Preferred result |
|---|---|---|
| Calinski-Harabasz Index | Measures cluster separation | Higher |
| Davies-Bouldin Index | Measures cluster similarity | Lower |
| Silhouette Score | Measures cluster cohesion and separation | Higher |
| Bayesian Information Criterion | Helps select GMM complexity | Lower |

These are clustering and model-selection metrics, not classification accuracy.

- Destination host
- Network protocol
- Source and destination ports
- Country
- Latitude and longitude

```text
AWS_Honeypot_marx-geo.csv
```

Place the dataset in the same directory as the notebook or update the CSV path in the configuration section.

## ⚠️ Limitations

- An anomaly does not necessarily represent a malicious IP.
- Unseen IP risk estimates may have limited evidence.
- IP geolocation is approximate.
- Threat-intelligence information may be incomplete or outdated.
- Reliable classification accuracy requires ground-truth labels.
- The current monitoring implementation does not replace a production-grade IDS or IPS.
